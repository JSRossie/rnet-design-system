VS Code Markdown Preview Target

This page simulates the VS Code built-in preview. It carries the real vscode-body class, so the type, color, metadata strip, stripe, and footer are exactly what markdown.css contributes. The live editor preview also layers VS Code's own body styles on top — open a real .md file there to see the genuine result.

A markdown document is most often read in the editor, so the VS Code preview is a named render target rather than an unsupported surface. It delivers correct type and color, both modes following the editor theme, and the chrome you see here: an accent stripe, the metadata strip above, a classification rule, and the footer below.

What carries the rendering

Two things, both shipping CSS only — no extension authored by the system:

  • colors_and_type.css recognizes VS Code's vscode-light and vscode-dark body classes, so the token set activates on the editor theme.
  • markdown.css carries its element rules under :is(.md, body.vscode-body) — one source, both scopes — and draws the preview chrome from the body box.

The metadata strip needs front matter in the page DOM, which the Microsoft-authored bierner.markdown-yaml-preamble extension supplies. It is the one external dependency of this target.

Setup

Point the preview at the system CSS in .vscode/settings.json:

{
  "markdown.styles": [
    "https://cdn.rossie.net/charts-and-vectors/css/v1/rnet.css"
  ]
}

Footer override

The footer wordmark is the one project-level knob. Set --doc-footer in a CSS file loaded after the bundle — a quoted string sets the text, none drops the footer, unset uses the system wordmark:

body.vscode-body { --doc-footer: "ACME ◇ INTERNAL"; }
